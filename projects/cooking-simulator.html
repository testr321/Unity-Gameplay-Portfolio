Cooking Simulator

3D first-person restaurant simulator. NPC customers queue at the door, order from a data-driven menu, and seat themselves as tables free up. The player grabs ingredients, cooks them to the right doneness, plates them, and validates each order against a Scriptable Object recipe before the customer's patience runs out.

My Contribution

Sole programmer. I built the full service loop across 24 C# scripts: NavMesh queueing and seating, Scriptable Object orders, cooking state, pick-up/drop, plating, and order validation.

  • Order validation (OrderScipt / OrderScript) — OverlapBox finds the plate; PlateScript.GetItemsOnPlate() is matched against a FoodItemScriptableObject (name, cooked, not burned)
  • NPC queue and seating (QueueManager, NPCSpawner, NPCController) on NavMesh — Z-offset slots, chair assignment, queue compression with +5 patience, exit via DestoryManager
  • Pick-up/drop and plating (PlayerPickUpDrop, ObjectGrabbable, PlateScript) — raycast grab, kinematic MovePosition lerp, runtime FixedJoints, no transform parenting
  • Cooking on the item (StoveScript → StartCook / StopCook) with raw → cooked → burned material swaps, plus fridge respawn (ShelfTrigger) and first-person move (PlayerMovement, MouseLook)

Technical Breakdown

Problem

A plate assembled at runtime is a physics stack of joints. Hard-coding dish names broke as soon as a recipe changed, and querying joints for "what's on the plate" was unreliable.

Solution

OrderScript OverlapBoxes for the PlateScript, then matches GetItemsOnPlate() against the recipe asset: item name, cooked flag, not burned. Menu entries live on MenuItemsScriptableObject / FoodItemScriptableObject.

Result

A new dish is an asset and a prefab — no code change. The same validator covers burgers, hotdogs, and custom menu items.

Reflection

What Went Well

  • Data-driven menu scaled to new dishes without code changes
  • NavMesh queueing and seating produced believable restaurant flow
  • Joint-based plate stacking gave carry behaviour physical credibility

What I Would Redesign

  • Replace FindObjectOfType service location with injected references or a service locator
  • Decouple the circular NPCController ↔ PlayerScript calls with an event system
  • Replace static scene gate flags with a proper game state manager
